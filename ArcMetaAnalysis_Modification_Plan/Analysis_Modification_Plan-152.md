# 极致性能夺回与 C 盘逻辑加固方案 —— Analysis_Modification_Plan-152.md

## 1. 任务背景
用户反馈当前 C++ 版在筛选和显示速度上均逊于 Rust 原版，且 C 盘扫描逻辑存在执行偏差（未生成缓存）。经审计，瓶颈在于扫描路径下的分配风暴以及搜索路径下的任务调度不均。

## 2. 问题定位
- **地雷 A：扫描路径的“三重分配” (Ingestion Allocation Churn)**
  - `loadMftDirect` 内部：`QString` -> `QByteArray` -> `std::string`。
  - **后果**：百万级扫描产生 300 万次内存碎片申请。
- **地雷 B：C 盘扫描的“静默夭折”**
  - `loadMftDirect` 对 `C:` 的某些受限 I/O 报错处理过于僵硬，导致稍微报错即放弃整个盘符的索引建立。
- **地雷 C：搜索任务的“长尾效应”**
  - `search` 的 `grainSize` 固定为 100,000。在百万级数据下，若某些分块包含大量匹配项，会导致该线程执行时间远超其他线程，产生体感延迟。

## 4. 详细解决方案

### 4.1 扫描链路“零转换”直连 (MftReader.cpp)
废除中间 `QString` 构造，直接从 UTF-16 到 SoA 池：
- **重构 `loadMftDirect`**：
  - 在 `RawEntry` 中仅存储偏移和长度。
  - 直接调用 `WideCharToMultiByte` 将 MFT 原始缓冲区内容转换到 UTF-8 临时堆栈区，然后直接 `memcpy` 到 `result.entries` 的预留池。
- **效果**：扫描速度预计提升 2-3 倍，达到或超越 Rust 原版。

### 4.2 搜索响应“极致压榨” (MftReader.cpp)
- **动态分块调度**：
  - 弃用固定的 `grainSize`，改用 `(totalCount / CPU核心数 / 4)` 的启发式分块。
  - **任务预取**：引入 `it_start` 与 `it_end` 智能裁剪，利用 `m_sorted_indices` 排除明显不匹配的前缀。
- **匹配加速**：
  - 在 `matchEntry` 内部直接操作 `char*` 指针。严禁任何 `QByteArray` 构造（对应 Plan-151 规约）。

### 4.3 C 盘扫描鲁棒性加固
- **分级容错**：修改 `loadMftDirect`。若 `C:` 的 `FSCTL_ENUM_USN_DATA` 遇到权限受限条目，跳过并记录警告，而非 `return false` 放弃整个盘符。
- **强行落盘**：确保 `saveDriveToCache` 在扫描完成 50% 时即触发第一次后台写入，防止因内存积压导致的写入失败。
